Why anumati is built the way it is: each significant decision as a short record (context, the decision, its consequences), in the ADR format. A decision is never edited away: a later one supersedes it. Sources: docs/adr.

ADR 0002 · Accepted

A consent gate, not a sandbox

AI agents need root for real work; copying sudo commands back and forth is slow and error-prone, and giving an agent passwordless sudo removes the human from the loop.

ADR 0003 · Accepted

Install root-owned in /usr/local

If the window or the runner were user-writable, the agent the window guards against could edit them.

ADR 0004 · Accepted

The window is not a child of the agent

A window started by the agent could be inspected (ptrace, /proc) or fed a different environment.

ADR 0005 · Accepted

Rename vayu-elevate to anumati, in its own repository

The tool is useful on any Linux desktop, not only Vayu, and Vayu's rule is that tools live in their own repositories.
